## Name of Target Application

**MoneyNote** — 단일 사용자용 오프라인 데스크톱 가계부 (Java Swing)

수입과 지출을 기록하고, 기간과 분류별로 집계하고, 예산을 넘으면 경고하는 프로그램이다. 체크포인트 1에서 정한 기능 10개를 사용자 목표 기준으로 5개 기능으로 다시 묶고, 기능마다 요구사항과 유스케이스를 정의한다.

## A Topic out of 5

**선택: 4. Household Account Book Program (가계부 프로그램)**

가계부 데이터는 날짜, 금액, 분류를 갖는 시계열 거래다. 거래는 계속 쌓이고, 기간별·분류별로 합산하고 비율을 내는 파생 계산이 반드시 뒤따른다. 그래서 표 조회, 폼 검증, 파일 저장이라는 기본기 위에 집계, 시각화, 규칙 기반 경고를 얹을 수 있다. 다섯 후보 중 이 조건을 모두 갖춘 주제는 가계부뿐이다.

## Characteristics

- **C1 단일 사용자 오프라인 데스크톱** — 네트워크, 로그인, 서버가 없고 실행 즉시 사용한다.
- **C2 시계열 누적 데이터** — 날짜가 1차 정렬 키이고, 조회는 항상 기간을 전제로 한다.
- **C3 파생 계산 중심** — 월 합계, 잔액, 분류별 비중처럼 화면의 숫자 대부분이 계산 결과다.
- **C4 금액 데이터 무결성** — 금액은 원 단위 정수로 다루고 음수와 비숫자는 입력 단계에서 막는다.
- **C5 규칙 기반 능동 피드백** — 예산 사용률을 스스로 판정해 경고한다.
- **C6 시각화 요구** — 분류별 지출 비중을 그래프로 보여준다.

## Functions

체크포인트 1의 기능 10개(F1~F10)를 사용자가 달성하려는 목표 단위로 묶어 5개 기능으로 정리했다. 하나의 목표를 이루는 동작(예: 등록과 수정·삭제)은 하나의 기능으로 합쳤다. 사용자가 직접 수행하지 않는 F10(저장 및 불러오기)은 기능에서 빼서 비기능 요구사항(NFR2, NFR4)으로 옮겼다.

| 번호 | 기능 | 포함한 1차 기능 | 유스케이스 |
|---|---|---|---|
| FN1 | 거래 기록 관리 | F1 거래 등록, F2 거래 수정 및 삭제 | UC1 |
| FN2 | 거래 조회 및 검색 | F3 거래 목록 조회, F4 검색 및 필터 | UC2 |
| FN3 | 분류 관리 | F5 분류 관리 | UC3 |
| FN4 | 수지 요약 및 지출 통계 | F6 월별 수지 요약, F7 분류별 지출 통계 및 그래프 | UC4 |
| FN5 | 예산 및 고정 지출 관리 | F8 예산 설정 및 초과 경고, F9 고정 지출 반복 등록 | UC5 |

- **FN1 거래 기록 관리** — 수입과 지출을 등록하고, 잘못 입력한 거래를 수정하거나 삭제한다. 모든 데이터가 이 기능에서 생긴다.
- **FN2 거래 조회 및 검색** — 거래를 표로 보고, 기간·유형·분류·메모 키워드로 걸러 건수와 합계를 확인한다.
- **FN3 분류 관리** — 식비, 교통 같은 분류를 추가하고 이름을 바꾸거나 삭제한다. 사용 중인 분류는 삭제할 수 없다.
- **FN4 수지 요약 및 지출 통계** — 한 달의 총수입, 총지출, 잔액을 보고 지출을 전월과 비교하고, 분류별 지출 비중을 막대그래프로 본다.
- **FN5 예산 및 고정 지출 관리** — 분류별 월 예산을 정해 사용률을 3단계로 경고받고, 월세처럼 매달 나가는 지출을 규칙으로 등록해 자동 생성한다.

## Requirement Lists

### 기능 요구사항 (Functional Requirements)

| ID | 요구사항 | 기능 |
|---|---|---|

| FR2 | 금액이 비었거나 숫자가 아니거나 0 이하이면 저장을 거부하고, 분류를 고르지 않으면 저장할 수 없어야 한다. 미래 날짜는 사용자 확인을 받아야 한다. | FN1 |
| FR3 | 사용자는 목록에서 고른 거래를 수정하거나, 확인을 거쳐 삭제할 수 있어야 한다. | FN1 |
| FR4 | 거래 목록은 날짜 내림차순 표로 보여야 하고, 컬럼 헤더를 눌러 다시 정렬할 수 있어야 한다. | FN2 |
| FR5 | 기간, 유형, 분류, 메모 키워드를 AND 조건으로 걸러 조회하고, 결과의 건수와 합계를 보여야 한다. | FN2 |
| FR6 | 이번 달, 지난 달, 올해 같은 빠른 기간 선택을 제공해야 한다. | FN2 |
| FR7 | 사용자는 분류를 추가하고 이름을 바꾸고 삭제할 수 있어야 하며, 최초 실행 시 기본 분류가 만들어져 있어야 한다. | FN3 |
| FR8 | 거래가 쓰고 있는 분류는 삭제를 막고 사용 건수를 알려야 하며, 같은 유형 안에서 이름이 겹치면 거부해야 한다. | FN3 |
| FR9 | 선택한 월의 총수입, 총지출, 잔액과 전월 대비 지출 증감률을 보여야 한다. | FN4 |
| FR10 | 선택한 월의 지출을 분류별로 합산해 비중과 함께 막대그래프로 보여야 한다. | FN4 |
| FR11 | 사용자는 분류별 월 예산 한도를 정할 수 있어야 하고, 사용률 80% 미만은 정상, 80~100%는 주의, 100% 이상은 초과로 표시해야 한다. | FN5 |
| FR12 | 사용자는 고정 지출 규칙(분류, 금액, 매월 결제일)을 등록할 수 있어야 하고, 프로그램은 시작할 때 이번 달 고정 지출을 한 번만 자동 생성해야 한다. | FN5 |

## Usecases

액터는 모두 **사용자**(가계부를 쓰는 개인) 한 명이다. 시스템은 MoneyNote 프로그램이며, 메인 창은 거래내역, 통계, 예산 탭으로 구성된다.

### UC1. 거래 기록 관리

| 항목 | 내용 |
|---|---|
| 유스케이스 | UC1 거래 기록 관리 |
| 액터 | 사용자 |
| 관련 요구사항 | FR1, FR2, FR3, NFR3, NFR5 |
| 사전 조건 | 프로그램이 실행되어 거래내역 탭이 열려 있다. 분류가 하나 이상 있다. |
| 기본 흐름 (등록) | 1. 사용자가 등록 버튼을 누른다. 2. 시스템이 날짜가 오늘로 채워진 입력 창을 연다. 3. 사용자가 유형을 고른다. 4. 시스템이 유형에 맞는 분류만 목록에 보여준다. 5. 사용자가 금액, 분류, 결제수단, 메모를 입력하고 저장을 누른다. 6. 시스템이 입력값을 검증하고 새 id를 붙여 거래를 저장한다. 7. 시스템이 목록, 통계, 예산 화면을 다시 계산해 보여준다. |
| 대안 흐름 (수정) | A1. 사용자가 목록에서 거래를 고르고 수정을 누른다. A2. 시스템이 기존 값이 채워진 입력 창을 연다. A3. 사용자가 값을 바꾸고 저장하면 시스템은 같은 id로 거래를 바꾸고 7단계로 간다. |
| 대안 흐름 (삭제) | B1. 사용자가 거래를 고르고 삭제를 누른다. B2. 시스템이 "이 거래를 삭제하시겠습니까?"를 묻는다. B3. 사용자가 예를 누르면 시스템은 거래를 지우고 7단계로 간다. 아니오를 누르면 아무것도 바꾸지 않는다. |
| 예외 흐름 | E1. 금액이 비었거나 숫자가 아니거나 0 이하이면 입력 확인 메시지를, 분류를 고르지 않았으면 "분류를 선택하세요."를 보이고 5단계로 돌아간다. E2. 날짜가 미래이면 "미래 날짜입니다. 이대로 등록할까요?"를 묻고, 아니오면 5단계로 돌아간다. E3. 거래를 고르지 않고 수정·삭제를 누르면 "먼저 목록에서 거래를 선택하세요."를 보이고 끝낸다. E4. 입력 창에서 취소를 누르면 저장하지 않고 끝낸다. |
| 사후 조건 | 거래 목록이 바뀌고, 월 요약·분류 통계·예산 사용률이 새 값으로 갱신된다. |

### UC2. 거래 조회 및 검색

| 항목 | 내용 |
|---|---|
| 유스케이스 | UC2 거래 조회 및 검색 |
| 액터 | 사용자 |
| 관련 요구사항 | FR4, FR5, FR6 |
| 사전 조건 | 프로그램이 실행되어 있다. |
| 기본 흐름 | 1. 사용자가 거래내역 탭을 연다. 2. 시스템이 거래를 날짜 내림차순 표로 보여주고, 아래에 건수, 수입, 지출, 잔액을 표시한다. 3. 사용자가 기간(시작일~종료일), 유형, 분류, 메모 키워드 중 원하는 조건을 입력하고 조회를 누른다. 4. 시스템이 비어 있지 않은 조건을 모두 만족하는 거래만 표에 남긴다. 5. 시스템이 결과의 건수와 합계를 다시 표시한다. |
| 대안 흐름 | A1. 3단계에서 사용자가 이번 달, 지난 달, 올해 중 하나를 누르면 시스템이 기간을 채우고 4단계로 간다. A2. 사용자가 컬럼 헤더를 누르면 시스템이 그 컬럼 기준으로 표를 다시 정렬한다. |
| 예외 흐름 | E1. 시작일이 종료일보다 늦으면 "시작일이 종료일보다 늦어 두 값을 바꿔 조회합니다."를 알리고 두 값을 바꿔 조회한다. E2. 날짜 형식이 틀리면 입력 확인 메시지를 보이고 3단계로 돌아간다. E3. 결과가 0건이면 "조건에 맞는 거래가 없습니다."를 표시한다. |
| 사후 조건 | 데이터는 바뀌지 않는다. 표에는 조건에 맞는 거래만 보인다. |

### UC3. 분류 관리

| 항목 | 내용 |
|---|---|
| 유스케이스 | UC3 분류 관리 |
| 액터 | 사용자 |
| 관련 요구사항 | FR7, FR8 |
| 사전 조건 | 프로그램이 실행되어 있다. 최초 실행이면 시스템이 식비, 교통, 주거, 통신, 문화, 급여 같은 기본 분류를 만들어 둔다. |
| 기본 흐름 (추가) | 1. 사용자가 분류 관리 화면을 연다. 2. 시스템이 분류 목록과 분류별 사용 건수를 보여준다. 3. 사용자가 이름과 유형(수입/지출)을 입력하고 추가를 누른다. 4. 시스템이 이름 중복을 검사하고 분류를 저장한다. 5. 시스템이 거래 입력 창과 예산 화면의 분류 목록을 갱신한다. |
| 대안 흐름 (이름 변경) | A1. 사용자가 분류를 고르고 새 이름을 입력한다. A2. 시스템이 중복을 검사하고 이름을 바꾼다. 이 분류를 쓰는 거래에도 새 이름이 보인다. |
| 대안 흐름 (삭제) | B1. 사용자가 분류를 고르고 삭제를 누른다. B2. 이 분류를 쓰는 거래가 없으면 시스템이 확인을 받고 삭제한다. |
| 예외 흐름 | E1. 같은 유형에 같은 이름이 있으면 거부하고 3단계로 돌아간다. E2. 이 분류를 쓰는 거래가 N건 있으면 "이 분류를 사용하는 거래가 N건 있습니다. 먼저 정리하세요."를 보이고 삭제하지 않는다. E3. 이름이 비어 있으면 거부한다. |
| 사후 조건 | 분류 목록이 바뀌고, 거래가 없는 분류만 삭제된다. |

### UC4. 수지 요약 및 지출 통계 조회

| 항목 | 내용 |
|---|---|
| 유스케이스 | UC4 수지 요약 및 지출 통계 조회 |
| 액터 | 사용자 |
| 관련 요구사항 | FR9, FR10, NFR5 |
| 사전 조건 | 프로그램이 실행되어 있다. |
| 기본 흐름 | 1. 사용자가 통계 탭을 연다. 2. 시스템이 조회 월을 이번 달로 채운다. 3. 시스템이 그 달의 총수입, 총지출, 잔액을 구하고, 지출을 전월과 비교한 증감액과 증감률을 표시한다. 4. 시스템이 그 달의 지출을 분류별로 합산하고 비중을 구해 금액이 큰 순서로 정렬한다. 5. 시스템이 분류별 금액과 비중을 막대그래프로 그리고, 가장 많이 쓴 분류를 다른 색으로 강조한다. |
| 대안 흐름 | A1. 사용자가 조회 월(yyyy-MM)을 바꾸고 조회를 누르면 시스템이 3단계부터 다시 계산한다. A2. 다른 탭에서 거래가 바뀌면 시스템이 자동으로 3단계부터 다시 계산한다. |
| 예외 흐름 | E1. 조회 월 형식이 틀리면 "조회 월은 yyyy-MM 형식으로 입력하세요."를 보이고 이전 결과를 유지한다. E2. 그 달에 거래가 없으면 모든 값을 0으로 보인다. E3. 전월 지출이 없어 비교할 수 없으면 증감률 대신 "비교 데이터 없음"을 보인다. E4. 지출이 0원이면 그래프 대신 "표시할 지출 내역이 없습니다."를 그린다. E5. 분류가 8개를 넘으면 상위 8개만 그리고 나머지는 기타로 묶는다. |
| 사후 조건 | 데이터는 바뀌지 않는다. |

### UC5. 예산 및 고정 지출 관리

| 항목 | 내용 |
|---|---|
| 유스케이스 | UC5 예산 및 고정 지출 관리 |
| 액터 | 사용자 |
| 관련 요구사항 | FR11, FR12, NFR5 |
| 사전 조건 | 프로그램이 실행되어 있고 지출 분류가 하나 이상 있다. |
| 기본 흐름 (예산 설정) | 1. 사용자가 예산 탭을 연다. 2. 시스템이 이번 달 분류별 사용액, 한도, 사용률, 상태를 표로 보여준다. 3. 사용자가 분류를 고르고 한도 금액을 입력한 뒤 예산 설정을 누른다. 4. 시스템이 한도를 저장한다. 5. 시스템이 사용률을 다시 구해 80% 미만은 정상(초록), 80% 이상 100% 미만은 주의(노랑), 100% 이상은 초과(빨강)로 표시하고, 초과면 초과 금액도 보여준다. |
| 대안 흐름 (고정 지출 등록) | A1. 사용자가 고정 지출 화면에서 분류, 금액, 매월 결제일, 메모를 입력하고 저장한다. A2. 시스템이 규칙을 저장한다. A3. 이후 프로그램이 시작될 때마다 시스템은 활성 규칙 중 이번 달에 아직 만들지 않은 것을 거래로 만들고, 만든 건수를 알린다. |
| 대안 흐름 (조회 월 변경) | B1. 사용자가 조회 월을 바꾸고 조회를 누르면 시스템이 그 달 기준으로 2단계를 다시 보여준다. |
| 예외 흐름 | E1. 분류를 고르지 않으면 "분류를 선택하세요."를 보인다. E2. 한도가 숫자가 아니거나 0 이하이면 거부하고 3단계로 돌아간다. E3. 예산이 없는 분류는 판정하지 않고 미설정으로 표시한다. E4. 결제일이 그 달에 없으면(예: 2월 31일) 그 달 마지막 날로 만든다. E5. 사용자가 자동 생성된 거래를 지웠다면 같은 달에 다시 만들지 않는다. |
| 사후 조건 | 예산 한도나 고정 지출 규칙이 저장되고, 예산 상태가 최신 지출 기준으로 표시된다. |
